# CI and Testing Guide

**Audience:** contributors working on the registry codebase. For operator-facing deployment notes, see [reference/configuration.md](../05-reference/03-configuration.md) and [operations/ops.md](../06-operations/01-ops.md).

All gates the project enforces are `make` targets defined in the root `Makefile`. CI platforms wire to those targets — they do not redefine the commands. This means the same gates run identically in local dev, in pre-commit, and in any CI runner. The list below is derived from the `Makefile`'s `all` target; if the two ever disagree, the `Makefile` is right.

---

## Quick reference

```bash
make all                # everything a PR must pass (see composition below)
make lint               # ruff check — style + correctness lints
make format-check       # ruff format --check — formatting gate (read-only)
make format             # ruff format — apply formatting (writes files)
make typecheck          # mypy --strict across source roots
make doc-refs           # no internal-doc references in shipped code
make test-hygiene       # phase-naming, import direction, migration naming, visibility chokepoint, state access, assertion-less tests
make privileged-writes  # privileged tables written through their one module only
make usage-boundary     # usage data stays non-authoritative
make reachability-audit # every quarantined memory service has a live production caller
make env-documented     # .env.example and the configuration reference agree
make task-records       # planning workspace's task plans don't contradict themselves (local-only, see below)
make seeds-validate     # seeds/ capabilities validate against the capability JSON Schema
make test-unit          # unit tests — pure Python, no DB, with the coverage ratchet
make test-integration   # integration tests — real Postgres, slow
make test-conformance   # conformance suite — OpenAPI drift, tenant isolation, MCP catalog
make test-perf          # SLO perf tests — latency p95 verification, marked @slow
make test               # unit + conformance (fast gates for daily dev)
```

`make all` runs, in order: `lint format-check typecheck doc-refs test-hygiene privileged-writes usage-boundary reachability-audit env-documented task-records seeds-validate test` (where `test` is `test-unit test-conformance`). `test-integration` and `test-perf` are not part of `make all` — see [CI platform wiring](#ci-platform-wiring) for where they run instead.

## Gate descriptions

### lint (`make lint`)

Runs `ruff check` across `registry/` and `scripts/`. Catches style violations, unused imports, and common correctness issues. Required on every PR.

### format-check (`make format-check`)

Runs `ruff format --check` — fails if any file needs reformatting. Use `make format` (writes files) to fix locally before pushing. Required on every PR.

### typecheck (`make typecheck`)

Runs `mypy --strict` on `registry/` and `scripts/`. Required on every PR.

### doc-refs (`make doc-refs`)

Verifies no shipped file contains references to internal planning documents (ADR numbers, PRD feature IDs, task IDs, TDD section citations, phase labels). Walks `registry/`, `scripts/`, `tests/`, `eval/`, `CONTRIBUTING.md`, `README.md`, `.env.example`, and `deploy/helm/`. Exits non-zero with a `file:line` list on any hit.

The rule: code comments explain the reason in the code's own vocabulary, not where the rule was decided. See the repo-root `CLAUDE.md` for the full list of forbidden patterns and the intentional-bypass mechanism.

### test-hygiene (`make test-hygiene`)

Runs six independent checks:

- No test file under `tests/` is named with a delivery-phase label, and no test comment contains a stale phase marker (`scripts/check_no_phase_named_tests.py`). Lines ending `# test-hygiene: intentional` are exempt when "phase" is a genuine domain term.
- `scripts/` never imports `tests/` — the reverse direction is fine and expected (`scripts/check_import_direction.py`).
- New Alembic migration filenames are named for what they do, not for a delivery phase (`scripts/check_migration_naming.py`).
- A module that queries the `entities` table must import the visibility chokepoint (`service/governance/visibility.py`) or be named in that script's allowlist with a reason (`scripts/check_visibility_chokepoint.py`).
- Services are read from the typed `Services` container, not from raw `app.state`/`request.state` lookups outside the wiring layer (`scripts/check_state_access.py`).
- Every `test_*` function actually asserts something — no test that runs code and checks nothing (`scripts/check_test_assertions.py`).

Each of the six scripts supports `--explain` and `--paths` for scoped, human-readable runs.

### privileged-writes (`make privileged-writes`)

Verifies that tables whose rows establish trust the rest of the system relies on (`tenants`, `memory_claims`, `memory_claim_provenance`) are written only through their one designated module (`scripts/check_privileged_writes.py`).

### usage-boundary (`make usage-boundary`)

Verifies usage data (who called what) stays non-authoritative: only `registry/usage/` may query the usage tables, importers must be declared with a reason, and `registry/usage/` may not import the service or ARC layers (`scripts/check_usage_boundary.py`).

### reachability-audit (`make reachability-audit`)

Verifies every quarantined memory-curation service (`promotion.py`, `curation_queue.py`, `contest.py`, `confirmation.py`, `calibration.py`, `capability_requests.py`, `source_governance.py`, `source_ingest.py` under `registry/service/memory/`) is actually called by a route, an MCP tool, or a scheduled job — not just exercised by its own tests (`scripts/check_memory_reachability.py`).

### env-documented (`make env-documented`)

Verifies `.env.example` and [`docs/05-reference/03-configuration.md`](../05-reference/03-configuration.md) agree in both directions: every variable in one appears in the other (`scripts/check_env_documented.py`). Does not check that the code reads the variable — that is `Settings`' own job.

### task-records (`make task-records`)

Verifies the planning workspace's task plans don't contradict themselves (a task marked `done` next to a phase header still marked pending, a `blocked` task with no blocker stated, and similar shapes). Local-only by design: it reads a sibling checkout of the planning repository and skips with a note (not a failure) when that checkout isn't present — which is every CI job, since the planning workspace is a separate repository (`scripts/check_task_records.py --if-present`).

### seeds-validate (`make seeds-validate`)

Validates every capability entity under `seeds/` against the capability JSON Schema (`seeds/_templates/capability-schema.json`), using the same merged-attribute-state rules the seed loader uses. Runs without a database (`scripts/validate_seeds.py`).

### auth-consolidation-gate (`make auth-consolidation-gate`)

Fails if any legacy auth-path symbol (the old `auth_mode` discriminator, `RSAM`/`rsam` naming, the deleted `api_token` validator/hasher/admin path) survives outside migrations. Not part of `make all` — CI invokes it as its own step alongside the `make all` gates.

### test-unit (`make test-unit`)

Runs all tests under `tests/unit/`. Unit tests are pure Python with no database dependency. They use SQL-string-keyed `AsyncMock` routers to fake the DB layer. This is the default home for new tests. Runs with the coverage ratchet — `--cov=registry --cov-report=term-missing:skip-covered --cov-fail-under=80`. The floor only ever rises: a PR that would drop unit-scope coverage below it must add coverage or raise the floor deliberately in the same change.

### test-integration (`make test-integration`)

Runs `tests/integration/` with a 180-second timeout. Runs against a real Postgres — see [Environment for tests](#environment-for-tests) for where it comes from. Promotes to integration when the unit version cannot exercise the real code path (triggers, constraints, partitioning, cross-service behaviour).

### test-conformance (`make test-conformance`)

Runs `tests/conformance/` with a 60-second timeout. These are contract-drift gates:

- **OpenAPI snapshot** — verifies the committed `openapi.json` matches the live schema.
- **MCP tool catalog** — verifies the registered MCP tools match the expected list.
- **Cross-tenant isolation invariants** — verifies every query path funnels through the visibility chokepoint.

### test-perf (`make test-perf`)

Runs `tests/perf/` with a 300-second timeout. Tests are marked `@pytest.mark.perf @pytest.mark.slow` and excluded from `make test` (the daily fast gate). Runs nightly and on demand — see [CI platform wiring](#ci-platform-wiring).

### test-airgap (`make test-airgap`)

Builds the Docker image and proves it embeds and searches with no network egress: runs the built image on an isolated Docker network, migrates, and drives ingest, drain, and an ANN search against a Postgres on the same network. Needs Docker; not part of `make all`.

### test-smoke (`make test-smoke`)

Full-stack auth smoke test against whichever stack is running. Requires a stack (`make dev-up` or `docker compose up -d`) — a skip counts as a failure here, unlike an ad hoc pytest run, so "no stack" and "auth is broken" can never both read as green.

## Test pyramid

Pick the right bucket when adding a test:

| Bucket | When to use | Notes |
|---|---|---|
| `tests/unit/` | Default. Pure Python, no DB. Use SQL-string-keyed `AsyncMock` to fake the DB layer. | Fast; carries the coverage ratchet. |
| `tests/integration/` | Only when behaviour spans more than one service or requires real SQL (triggers, constraints, partitioning). | Slow; needs a real Postgres. |
| `tests/conformance/` | Contract drift gates. Run before tagging a release. | Moderate; needs a real Postgres. |
| `tests/perf/` | SLO verification. Run in the release pipeline and nightly only. | Slow; marked `@slow`. |

When in doubt, write a unit test first. Promote to integration only when the unit version cannot exercise the real code path.

## Pre-commit hooks

```bash
pre-commit install
```

After installation, every `git commit` runs four hooks, all local invocations of the same tools pinned in `pyproject.toml`'s `dev` extra: `ruff check` (lint), `ruff format --check` (format-check), `mypy --strict` (typecheck), and the doc-refs gate. They share the exact commands CI runs — no separate config. The remaining `make all` gates (test-hygiene, privileged-writes, usage-boundary, reachability-audit, env-documented, seeds-validate, and the test suites) are not wired into pre-commit; run `make all` locally or rely on CI to catch them.

## CI platform wiring

One example wiring ships with the project, under `.github/workflows/`:

- `ci.yml` — the PR and nightly pipeline. Runs on every push/PR touching shipped paths, plus a nightly `perf` job. It wires the `make all` gates as parallel jobs (lint-family gates in one job, `typecheck` and `test-unit` each in their own job) rather than one flat `make all` invocation, then chains `test-integration` → `test-conformance`. It also runs `make auth-consolidation-gate`, which is a CI step but not part of `make all`. A `native-stack` job repeats the integration/conformance suites against the locally-managed Postgres path (no container runtime) and exercises a real `dev-up` → `dev-token` → JWT → authenticated-call round trip. An `image` job builds the Docker image and runs `make test-airgap`.
- `release.yml` — the tag-triggered release pipeline. Mirrors `ci.yml`'s gate list, then adds a k6 read-smoke job against the dev stack, followed by image build, keyless cosign signing, SBOM generation, Helm chart packaging, and the GitHub release.

Any CI runner (GitLab CI, Jenkins, Buildkite, CircleCI, Azure DevOps, Bitbucket Pipelines, a plain `bash` script) that can invoke `make` can wire the same gates; neither workflow file is required, and either can be deleted without affecting what the gates check.

A typical PR pipeline runs:

```
make all      →  lint + format-check + typecheck + doc-refs + test-hygiene +
                  privileged-writes + usage-boundary + reachability-audit +
                  env-documented + task-records + seeds-validate + test-unit + test-conformance
make auth-consolidation-gate   (CI-only step, not part of `make all`)
```

A release pipeline adds:

```
make test-integration
make test-perf
make openapi-export   (verify openapi.json is committed and current)
make build-docker
make helm-package
```

## Environment for tests

Unit tests need no environment variables — the fake DB layer requires no database connection.

Integration and conformance tests need a real Postgres 16 with pgvector. Where it comes from is selected by `REGISTRY_TEST_PG`:

| Value | Behaviour |
|---|---|
| `auto` (default) | `DATABASE_URL` if set; else testcontainers if a container runtime answers; else a locally managed cluster. |
| `external` | Use `DATABASE_URL`. The schema must already be at head. |
| `testcontainers` | Always testcontainers. Started and stopped automatically. |
| `devstack` | Always a locally managed cluster. No container runtime needed. |

A CI runner with a container runtime therefore needs no configuration — `auto` picks testcontainers. A runner without one either sets `DATABASE_URL` to a service container, or installs the `devstack` extra and lets `auto` manage a cluster itself.

Every mode gives each session a freshly created, freshly migrated database that is dropped afterwards.

## Regenerating the OpenAPI snapshot

The committed `openapi.json` must match the live schema. Regenerate it with:

```bash
make openapi-export
```

Then commit the updated file. The conformance suite (`make test-conformance`) fails if the committed file is stale.

## Adding new Make targets

If you add a new gate, add it to the `Makefile` at the repo root under the appropriate section. Wire it into `make all` if it must pass on every PR. Keep each target as a single command or short pipeline — no logic in Make beyond invocation. Document what it does in the `## <description>` inline comment that `make help` prints.
